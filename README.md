# 淡江大學領袖禪學社 · 專屬 AI 代理

一個知道社團是誰、會照社團規矩做事，而且**會實際把檔案做出來**的 AI 助理。
不是給你建議，是直接產出試算表、企劃書、簡報、Google 表單。

它讀得到：社團知識庫、八份任務劇本，以及**共用雲端 108–115 學年度累積的
507 份歷年檔案**（企劃書、活動細流、社評報告、社課簡報、IG 文案、財務表、
挑戰營資料），所以做出來的東西跟社團一直以來的格式對得上。

用 NVIDIA Build 的**免費模型**驅動，不用付月費。

---

## 三分鐘上手

### 1. 拿一組免費的 NVIDIA 金鑰

到 <https://build.nvidia.com/settings/api-keys> 註冊並產生金鑰。
不用信用卡，註冊送 1,000 點推論額度（可申請加到 5,000），每分鐘 40 次請求。
金鑰長得像 `nvapi-xxxxxxxxxxxx`。

### 2. 雙擊 `啟動.bat`

第一次會自動：建立 Python 環境 → 安裝套件 → 開記事本讓你貼金鑰。
把 `.env` 裡這一行換成你的金鑰後存檔關閉：

```
NVIDIA_API_KEY=nvapi-你的金鑰
```

### 3. 瀏覽器會自動打開 <http://127.0.0.1:8848>

直接講話就好。例如：

> 幫我做一份 115 學年度上學期的社課排程表，18 週

它會先查社團知識庫，再把 `.xlsx` 做出來，畫面上直接給你下載連結。

要停止：回到黑色視窗按 `Ctrl+C`。

## 它會做什麼

| 工具 | 產出 | 用在哪 |
|---|---|---|
| 查詢社團知識庫 | — | 動手前一定先查，確保內容符合社團實況與語氣 |
| 建立試算表 | `.xlsx` | 社課排程、招生名單、分工表、預算表、器材清單、評鑑資料 |
| 建立文件 | `.docx`（可附 `.md`） | 招生企劃、活動企劃書、教案、交接手冊、評鑑報告、公文 |
| 建立簡報 | `.pptx` | 社課投影片、招生說明會、幹部交接、評鑑簡報 |
| 產生 Google 表單 | `.gs` + 說明 | 報名表、回饋問卷、意願調查（貼到 Apps Script 一鍵生成） |

試算表會自動排版：標題列上色、凍結首列、自動欄寬、篩選器，數字存成數值型別
（所以 `=SUM()` 之類的公式可以用）。

### 為什麼 Google 表單要多一個步驟

Google 沒有可以直接呼叫的表單建立 API（Forms API 要另外開 GCP 專案跑 OAuth）。
所以代理改成產一支 Apps Script：

1. 開 <https://script.google.com/home/projects/create>
2. 把產出的 `.gs` 內容整份貼進去
3. 按「執行」→ 第一次會要授權（選帳號 →「進階」→「前往…（不安全）」→「允許」）
4. 看「執行紀錄」，裡面有表單編輯連結、填寫連結、回覆試算表連結

表單會建在**你自己的 Google 帳號**底下，不經過任何第三方。

## 它不會做什麼（刻意的）

代理被明確禁止編造以下每年變動的資訊 —— 查不到就會填「待填」或直接問你：

- 當學期社長與幹部姓名、聯絡方式
- 社課的確切時間、地點、教室
- 社費金額
- 報名連結、表單網址
- 具體日期

另外它不會寫療效宣稱（治病、改善憂鬱、保證成功、改運），也不會把對外文宣寫成宗教招募 ——
這兩條寫在系統提示與任務劇本裡。

## 產出落點：本機還是雲端

介面右上角可以切換，每次對話也可以口頭指定（「這份放雲端」）。

- **本機**（預設）：存到 `outputs/日期/`，畫面上可直接下載。
- **Google 雲端**：上傳到「淡大領共用雲端」，需要先做下面的設定。
- **本機＋雲端**：兩邊都放。

### 設定雲端上傳

1. 到 <https://console.cloud.google.com/> 建一個專案
2. 「API 和服務」→ 啟用 **Google Drive API**
3. 「憑證」→ 建立憑證 → **OAuth 用戶端 ID** → 應用程式類型選「**電腦版應用程式**」
4. 下載 JSON，存成 `data/google_credentials.json`
5. 重新啟動。第一次選「Google 雲端」落點時會跳瀏覽器要你登入授權，之後就不用了。

沒設定也沒關係 —— 上傳失敗不會中斷，檔案照樣存在本機。

> 部署到伺服器時，OAuth 那套行不通（伺服器開不了瀏覽器）。
> 改用**服務帳號**：把服務帳號 JSON 放同一個位置，並把 Drive 目標資料夾
> 分享給該服務帳號的信箱（有編輯權限）。程式會自動辨認是哪一種憑證。

| 模型 | 適合 |
|---|---|

## 更新知識庫

代理的所有社團知識都來自 `knowledge/` 資料夾，都是純 Markdown，直接編輯就好：

```
knowledge/
├── 00_社團知識庫.md      ← 社團是誰、精神、十二特質、社課主題庫、招生方法、語氣指南
├── 劇本/                 ← 各種任務怎麼做才對
│   ├── 招生企劃.md
│   ├── 社課排程與籌備.md
│   ├── 營隊籌備.md
│   ├── 社團評鑑.md
│   ├── 幹部交接.md
│   ├── 經費預算.md
│   ├── 表單設計.md
│   └── 文宣與社群貼文.md
├── 雲端文件/             ← 共用雲端匯入的歷年檔案（見下）
└── 語料/                 ← LINE 歷史對話（預設空的，見下）
```

知識庫分兩個層級，代理會分開對待：

| 層級 | 是什麼 | 代理怎麼用 |
|---|---|---|
| **知識庫＋劇本** | 這件事該怎麼做（規範） | 照著做。檢索時保證至少佔 2 個名額 |
| **歷年檔案＋LINE 語料** | 以前實際怎麼做的（範例） | 對齊格式與寫法，但日期人名金額都是當年的，不當成今年的事實 |

**每學年至少更新一次** `00_社團知識庫.md` 的「§15 待補與年度更新」。
改完重新啟動，或呼叫 `POST /api/reindex` 就會重建索引。

想加新的任務類型（例如「講師邀請」），就在 `劇本/` 新增一個 `.md`，
照現有檔案的寫法：什麼時候用 → 產出什麼 → 必備欄位/章節 → 常見錯誤。

## 匯入共用雲端的歷年檔案

「淡大領共用雲端」有 108–115 學年度累積下來的 600 多份文件。把整個資料夾從
Google Drive 下載成 zip（會切成好幾個），放進一個資料夾，然後：

```bash
python scripts/ingest_drive.py --dry-run
```

先試跑看會處理什麼，沒問題就拿掉 `--dry-run`。腳本直接從 zip 串流讀取，
**不用解壓那 14GB** —— 裡面九成是照片影片，只有文件對代理有用。

實際匯入的量（2026/08）：

| 類型 | 份數 | 內容 |
|---|---|---|
| .docx | 148 | 企劃書、行政公版、會議紀錄、社評報告、IG 文案、交接文件 |
| .xlsx | 139 | 活動細流、財務總表、行事曆、進度表、器材清冊 |
| .pptx | 130 | 歷年社課簡報、社長時間、活動成果 |
| .pdf | 86 | 開示、成果報告、行政文件 |
| 其他 | 4 | 組織章程(.odt)、逐字稿 |
| **合計** | **507** | **約 82 萬字** |

跳過的：設計檔（海報、名牌、文宣 PDF，抽不到文字）、空白文件、
舊版二進位格式（.doc / .ppt，沒有可靠的純 Python 解析器）。

### 個資怎麼處理

社團雲端裡有大量同學的個人資料。腳本用**兩道防線**擋：

1. **欄位檢查** —— 表格標題出現「姓名／電話／手機／信箱／學號／系級」等欄位，
   就只保留欄位結構，不抽任何一列內容。
2. **內容檢查** —— 有些名冊根本沒有標題列（例如以個接人命名的分頁），
   欄位檢查完全無效。所以再抽樣看資料列，夠多列帶著聯絡方式或系級就一樣擋掉。

實測結果：**507 份裡有 103 份偵測到名冊，只保留欄位設計**。
稽核確認沒有任何未遮蔽的手機、市話、信箱、身分證或學號。

代理因此知道「招生進度表有哪些欄位」，但查不到任何一位同學的資料。

> 仍要注意：**幹部與講師的姓名會出現在企劃書、會議紀錄這類文件的正文裡**
> （例如「撰寫人：某某」「主持：某某」）。這些是社團自己的工作紀錄，
> 沒辦法在不破壞文件價值的前提下全部拿掉。若不接受，就不要匯入這批檔案 ——
> 代理光靠知識庫與劇本一樣能運作。

`knowledge/雲端文件/` 已寫進 `.gitignore`，不會進版控。

## 匯入 LINE 歷史對話（選用，預設關閉）

`D:\對話` 裡有 17 份社團 LINE 匯出記錄。匯入後代理就能參考歷屆怎麼籌備、
招生講了什麼、營隊踩過什麼坑。

```bash
python scripts/ingest_line.py --dry-run
```

先試跑看看會處理什麼，確認沒問題再拿掉 `--dry-run`。

匯入時會自動遮蔽：**手機、市話、電子郵件、身分證字號、9 碼學號、網址裡的 token**。

> **人名不會遮蔽**（不然對話會看不懂誰在講什麼）。
> 這代表被檢索到的對話片段，會隨著你的提問送到 NVIDIA 的伺服器。
> 覺得不妥就別匯入 —— 代理光靠知識庫與劇本已經能正常運作。

匯入後要在 `.env` 把 `ENABLE_LINE_CORPUS` 改成 `true` 才會生效。
`knowledge/語料/` 已經寫進 `.gitignore`，不會進版控。

## 部署到 Zeabur（給全社幹部用）

專案已經包好 `Dockerfile` 與 `zbpack.json`，Zeabur 會自動偵測。

1. 把專案推到 GitHub（`.env` 與 `data/` 已經在 `.gitignore` 裡，金鑰不會外流）
2. Zeabur → 新增服務 → 從 GitHub 部署
3. 在 Zeabur 的環境變數頁面設定：
   - `NVIDIA_API_KEY`
   - `DEFAULT_DESTINATION=drive`（**重要**，見下）
   - `DRIVE_FOLDER_ID`（要上傳到共用雲端的話）
4. 產生網域，把連結發給幹部

**容器重啟後本機檔案會消失**，所以部署版一定要把落點設成 `drive`，
並用服務帳號設定好 Drive 上傳，否則做出來的檔案沒地方放。

另外提醒：部署後任何拿到網址的人都能用，會消耗你的 NVIDIA 免費額度。
Zeabur 有密碼保護功能，建議開起來。

## 檢查與排錯

```bash
python scripts/selftest.py
```

不需要 API 金鑰，會檢查知識庫檢索、四個產出工具、參數容錯、以及完整的代理迴圈。

| 症狀 | 原因 |
|---|---|
| 畫面上方黃色警告說沒有金鑰 | `.env` 的 `NVIDIA_API_KEY` 沒填或填錯 |
| 「金鑰被拒（401）」 | 金鑰失效，重新產一組 |
| 「找不到模型（404）」 | 模型代號改了，到 build.nvidia.com/models 查，或換一個 |
| 「連續呼叫失敗」 | 免費額度用完、超過每分鐘 40 次、或網路問題 |
| 它只回文字不做檔案 | 換模型（有些模型工具呼叫服從度差）；或把需求講得更明確：「**做成試算表**」 |
| 「工具連續呼叫超過 8 輪」 | 模型卡住了，換模型或把需求拆小 |
| 產出內容有錯 | 先看是不是知識庫本身要更新，改 `knowledge/` 比改程式有效 |

### 檢索為什麼長這樣

刻意不用向量嵌入 —— 免費額度有限，而且 2,400 段這個規模用 BM25 已經夠準
（建索引 0.7 秒、單次查詢 6 毫秒），還能完全離線，知識庫不會為了建索引先送出去。

中文用字元二元組切詞，另外疊了四層修正，每一層都是實測踩到問題才加的：

| 機制 | 解決什麼 |
|---|---|
| 虛詞二元組過濾 | 「有哪」「可以」這種沒語意的組合反而 IDF 很高，會製造假命中 |
| 標題加權 ×3 | 〈社課主題庫〉整段都是課程名稱，內文幾乎不出現「社課」兩字 |
| 文件層級加權 | 劇本開頭的觸發關鍵字段落又短又密，會壓過同一份劇本裡真正有內容的段落 |
| 精選內容保留名額 | 加了 500 多份歷年檔案後「社課」IDF 幾乎歸零，劇本會被檔名特殊的歷年檔案整個擠出結果 |

檢索品質實測：24 個查詢（14 個「該怎麼做」＋10 個「找歷年實例」）top-5 全中。
