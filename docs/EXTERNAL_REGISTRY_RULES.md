# 外校 Registry 維運鐵律

外校（其他學校領袖社／禪學社）參考資料的新增與維護規則。內容彙整自
`app/research/entities.py` 的檔頭原則與 `knowledge/社群/其他禪學社IG公開資料.md`
自帶的治理規則——本文不新增規則，只把散在兩處的既有規則放在一頁。

## 為什麼有這份文件

「政大呢」事故的第一層根因：系統過去沒有任何地方記錄「研究對象是哪一所學校的
哪一個正式社團」，BM25 撈到什麼就答什麼。entity registry 是修復的核心，
維運時漏掉任何一條鐵律都可能讓事故重演。

## 鐵律

### 1. 資料檔與 Entity 條目必須同步

- 新增外校資料檔（`knowledge/社群/`）時，**必須**同步在 `app/research/entities.py`
  的 `EXTERNAL_ENTITIES` 加對應 `Entity` 條目，含官方 Instagram 帳號與
  `instagram_url`。
- 資料檔開頭必須帶「最後檢索日期：YYYY-MM-DD」標頭——`rag/metadata.py`
  由此帶入 `captured_at`，用來標註與判斷外校資料是否過舊。
- 沒加條目的學校會被視為「無已驗證社團」：系統會反問使用者、不生成外校事實。
  這是刻意的 fail-closed 設計，不是 bug。

### 2. 沒有已驗證來源的學校要用 `has_sources=False`

- registry 原則上只收「有已驗證公開來源」的實體（來源＝`knowledge/社群/` 參考檔）。
- 需要能被解析、但目前沒有任何已驗證公開來源的學校（現行案例：台大領袖社），
  條目必須標 `has_sources=False`：解析得到，但研究時只能回「找不到可靠來源」，
  不得生成事實。

### 3. 別名要過詞界防護測試

- 中文沒有空白詞界，兩字簡稱很容易被前一個字吞掉變成別的詞：
  「完成大合照」≠ 成大、「老師大概」≠ 師大、「行政大樓」≠ 政大。
- 新增或修改 `aliases` 後必須跑 `tests/test_entity_resolution.py`；容易誤判的
  短簡稱要在 `entities.py` 的 `_FALSE_PREV` 補上「前一個字是這些就不算」的黑名單。
- 黑名單原則：**寧可列少不列多**——漏擋只是多一次反問，
  錯擋會讓真正的外校查詢靜默變成內部模式。

### 4. 資料內容邊界（沿用 `knowledge/社群/` 檔案自帶規則）

- 只整理公開帳號頁面與公開搜尋結果可見的定位／主題；不保存留言區個資、
  不推測未公開資料。
- 這些檔案屬於 `external_public_reference`，永遠不是淡江的當期事實；
  不可把外校或基金會的時間、地點、社長、費用、報名連結、活動寫成淡江資料。
- 不可直接複製其他帳號的標語、貼文段落、圖片或影片；產淡江文案時只能參考
  內容架構與溝通策略，必須重新撰寫。
- 任何時間、地點、費用、講師、報名連結與當期幹部資料，一律回到淡江自己的
  `current_term.yaml` 或使用者明確提供的資料。
