# 工作台 UI/UX 重整（2026-08）

## 現況檢查與問題清單

1. 快捷入口有兩種不一致行為：有的開表單，有的只填入提示，使用者無法預測下一步。
2. 空白輸入框缺少任務方式、範例、文件與語音入口等可見引導。
3. 原流程送出後直接執行；模糊需求沒有「最少必要反問」與可確認的任務摘要。
4. SSE 進度會顯示工具名稱或技術流程，使用者難以判斷工作意義。
5. 停止、暫停、只重做失敗步驟雖有既有 API，前端缺乏可見而一致的操作入口。
6. 產出後主要只提供下載／重試，缺少修改、轉換格式與開始下一個任務的明確出口。
7. 行動版已有固定輸入框，但首頁缺少輸入前引導；桌面也未將任務摘要集中呈現。

## 使用者任務流程

```text
首頁
  ↓ 選任務方式／提示範例／填入常用任務
主要輸入框
  ↓
最少必要反問（0–3 題）
  ├─ 返回修改
  ├─ 先跳過（未知資料＝待填）
  └─ 確認開始
       ↓
可理解的任務進度 + 暫停／停止／摘要
       ↓
類型化輸出卡 + 下載／修改／轉換
       ↓
儲存到任務／補充資料／新任務
```

## 320–430px 方案

- 單欄，內容區不建立水平捲動；任務方式與提示列可橫向滑動。
- 所有直接操作按鈕最小 44×44px；清楚文字優先於未知圖示。
- composer 固定底部，使用 `100dvh`、safe area 與 `visualViewport`；文字框最高 160px。
- 研究、設定、任務摘要與反問一律使用可 Escape 關閉、可 Tab 導覽的底部 sheet。
- 進度以 `<details>` 收合，完成與失敗同時用文字與狀態色表達。

## 圖片附件

- 可加入最多兩張 JPG、PNG 或 WebP 圖片，每張上限 2MB；圖片只傳給當次模型請求，不寫入對話紀錄、資料庫或近期產出。
- 文字文件仍在瀏覽器端擷取文字後加入需求，不需額外上傳端點。
- 需在部署環境把 `NVIDIA_VISION_MODEL` 設為支援圖片輸入的 NVIDIA 模型；未設定時沿用既有 `NVIDIA_MODEL`，保持舊部署不受影響。

## 反問規則

- 先按需求歸類為網宣、活動、研究、文件或一般任務。
- 已提供足夠細節時直接顯示摘要，不追加問題。
- 模糊需求只問會改變成品的 1–3 題；選項優先，可補充文字。
- 使用者說「你決定」時採用卡片內預設，並在確認卡明示未知資料會標示「待填」。
- 「先跳過」不阻塞，改以「待填」送入現有任務流程。
- 本學期資料仍由既有後端判定；UI 不重複要求已可取得的資訊。
