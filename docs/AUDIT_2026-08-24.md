## 三、API 與 SSE 事件流程

**請求流**：瀏覽器 cookie fetch POST /api/chat → security_middleware（Origin CSRF＋每 IP 限流，main.py:63-88）→ general_router Depends(require_user)（231）→ chat()：每人 12/60s 限流（766）、附件 base64 驗證（777-788）、TURNS.start 單輪鎖（790-792）→ orchestrator.run_turn 非同步產生器（796-802）逐事件 yield → _sse() 序列化「data: {json}\n\n」（756-757）→ StreamingResponse text/event-stream（839-843）。

**LLM 流**：orchestrator → NvidiaClient.chat（共用 httpx 連線池，llm.py:87-97）→ NVIDIA Build，stream:False（llm.py:256）——SSE 是 orchestrator 事件粒度串流，不是 token 級。

**取消流**：前端停止鈕 POST /api/chat/cancel → TURNS.cancel 設 asyncio.Event → 串流迴圈 asyncio.wait 競速收尾（803-827）→ finally 釋放鎖（836）→ 最後必發 done（837）。

**SSE 事件清單**：main.py 自身：session（795）、cancelled（817,827）、error（831）、done（837）。orchestrator 轉發（main.py:823 原樣轉發、無 schema 驗證）：task_understood / plan_created / retrieval_started{queries} / retrieval_result / step_started / tool_started{name,label,preview} / tool_retrying / tool_completed / step_failed / message{text} / source_cards{cards} / contamination_warning{message,items,actions} / answer_review / clarification_needed / verification_started / verification_result / artifact_ready / repair_started / research_status / research_sources_saved / visual_analysis_* / task_paused|resumed|retry_ready|cancelled|failed|completed（orchestrator/__init__.py:221-1000）。

**已知結構問題**：SSE 未用標準 event:/id:/retry:、無 Last-Event-ID 續傳（main.py:756-757）；前端已支援解析 event: 但伺服器從不發（test_sse_stream.py:206-209），單邊實作。伺服器無心跳，兩次 yield 之間可長達數分鐘零輸出，只靠前端 120s watchdog。payload 的 name 欄位帶原始內部工具名（orchestrator:573,614,651），label 查無時 fallback 英文名（574 的 .get(tc.name, tc.name)）。
