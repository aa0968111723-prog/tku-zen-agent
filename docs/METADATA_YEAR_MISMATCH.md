# 學年度／學期系統性誤判清單

最後更新：2026-08-28（CST）
對照程式：`app/rag/metadata.py` `infer()`（main `51d503c7`）
本文件只記錄誤判與建議修法。**不改** `app/rag/metadata.py`。

推論與程式同一套，只看路徑 + label，不打開檔案本文：

```text
hay = f"{path.as_posix()} {label}"
label = f"歷年檔案／{父資料夾名}／{檔名不含副檔名}"
```

現行程式順序：

1. `_YEAR_SEM = r"(?<!\d)(1[0-2]\d)[-_ ]?([12])(?!\d)"` 先搜整個 hay
2. 找不到才 `_YEAR = r"(?<!\d)(1[0-2]\d)(?!\d)"`
3. 再找不到才 `_GREGORIAN`（西元 − 1911）
4. semester 再補「上學期／下學期／`-1 `／`-2 `」

資料夾名 `114學年度` **不符合** `_YEAR_SEM`（後面不是學期碼），所以檔名裡的 `1051`、`110-2`、`114-2` 會搶先。這是四類誤判的共同機制。

全庫學年度資料夾實際存在：108–115。沒有 105、121、122。

## (2) 121／122 學年度的來源

樹上沒有 121、122 學年度資料夾。`_YEAR` / `_YEAR_SEM` 的 year 組是 `1[0-2]\d`，合法範圍是 100–129，所以 121、122 **在字元類裡是合法年**，只是本庫不存在。

### 檔名裡看起來像 121／122 的 token

這些是月日（MMDD 或 `M_DD`），不是學年：

| 所在資料夾年度 | 檔名 token | 真實意思 | 現行程式（path+label）推出 | 檔名 |

原始雲端路徑還有一處目錄段 `1213_第八堂社課`（`112-1第八堂社課_做自己與他人生命中的天使112.12.13.md` 的檔頭來源），repo 扁平化後目錄名已不在 path 裡。`infer()` 不讀檔頭 `> 來源：`。

### 不要跟真的學年期碼搞混

`1121`、`1122`、`1141`、`1142` 是「學年 + 學期」連寫，本庫大量使用，必須繼續判對：

| 檔名 | 正確 | 不是 |
|---|---|---|
| `淡大1121.md`（卻在 **108** 夾） | 資料夾應優先 → 108 | 不是 121；也不是應該採檔名的 112-1 |
| `1121_文宣 (1).md`（112 夾） | 112 / 1 | 不是 121 |
| `1122招生文宣三折頁淡大版.md`（112 夾） | 112 / 2 | 不是 122 |
| `1141 期初茶會_浮花禪光.md` | 114 / 1 | — |
| `1142財務總表.md` | 114 / 2 | — |

### 現行程式會不會真的寫出 academic_year=121／122？

用**現行** `_YEAR_SEM` → `_YEAR`（都有 `(?!\d)`）對 repo path + label 跑，上表這些 4 位數日期**不會**變成 121／122：後面還有數字，look-ahead 擋下；資料夾的 `_YEAR` 先於檔名日期。

121／122 會「出現」的條件是下面任一：

- 拿掉 `(?!\d)`，`1224` → 122、`1210` → 121
- 只掃檔名、不看資料夾，且日期寫成獨立三碼（`121-…` / `122-…`）
- 將來若改去解析檔頭原始路徑，目錄段 `1213_第八堂社課` 在沒有 look-ahead 時會變成 121

所以這一類是「正則字元類過寬 + 月日 token 同形」的**潛在誤判源**。修法時資料夾優先 + 維持 look-ahead，即可同時封死。

正文裡的 121／122（經緯度 `121.84`、工作表名 `1218`、流水號）不在 hay 裡，現行 `infer()` 吃不到。

## 建議修法（尚未實作）

對標 `app/research/entities.py` 的詞界防護：`alias_mentioned()` 不讓「行政大樓」被判成政大、「完成大合照」被判成成大。學年解析要做同一件事——**短數字不能從更長、或更權威的結構裡被吞出來**。

### 1. 資料夾名優先

任何 path segment 符合 `^(1[0-2]\d)學年度$`，先定 `academic_year`，再在**同學年度**的前提下找學期。

```text
folder_year = first path segment matching ^(1[0-2]\d)學年度$
if folder_year:
    academic_year = folder_year
    semester = first _YEAR_SEM hit whose group(1) == folder_year
else:
    fall back to current _YEAR_SEM → _YEAR → _GREGORIAN
```

這一批 53 筆不一致會先被資料夾年拉回來。`1051` 再也贏不了 `114學年度`。

### 2. 為 1051 加詞界防護

即使沒有資料夾年（營隊夾、測試用假 path），`1051` 仍不可當學年期。建議當獨立 token 排除，而不是改 year 字元類（改成 `10[8-9]|11[0-5]` 會把未來 116 卡死）。

排除條件（擇一或並用，需測試）：

- hay 裡的 `1051` 若前後是 `-` / `_` / `：` / `:` / 字首，視為社團編號
- 或硬排除完整 token `1051`，不得寫成 `_YEAR_SEM` 的 year=105 semester=1

`1081`、`1101`、`1112`、`1121`、`1141`、`1142` 不是 1051，必須繼續命中。

### 3. 全形正規化（附帶）

解析前對 hay 做 NFKC，或至少把 `０-９` 轉半形。`114-２` 就會變成 `114-2`，semester=2。`10／01` 的斜線轉成 `/` 之後仍不是學年期，行為不變。

### 4. 不要做的事

- 不要從正文推學年（名冊、財務、公文號裡的 1051 會再炸一次）
- 不要用西元檔名覆寫資料夾年（`2026出隊.md` 在 113 夾，現行已是資料夾 113 先勝；維持）
- 不要把 year 字元類縮成「本庫現有的 108–115」——那是猜，不是規則
